# CANバスデータセット

本プロジェクトで使う生CANデータの説明。ここには「データが何か・どう並んで
いるか・プロファイリングで分かったこと」を記録する。

英語版: [`can_data.md`](can_data.md)

## 出所

- **車両**: Renault Euro VI 大型トラック(単一車両)。
- **収集**: 実路走行(ダイナモではない)。
- **規格**: SAE J1939 / FMS、250 kbit/s、全データフレーム、拡張(29ビット)ID。
- **内容**: 正常トラフィックのみ。記録内に攻撃・異常は含まれない。
- **原典**: トゥルク大学(University of Turku)J1939 トラックデータセット。
  https://etsin.fairdata.fi/dataset/7586f24f-c91b-41df-92af-283524de8b3e/data

## ディスク上の構成

```
data/
  part_1/   CSVファイル 約2,800
  part_2/   CSVファイル 約2,800
  part_3/   CSVファイル 約2,800
  part_4/   CSVファイル 約2,800
```

- CSVファイルは合計 **約11,194**。
- 各ファイルは連続した記録で **約10分 / 約50,000行**。
- 総フレーム数は **約5.6億** のオーダー。

各ファイルは独立した時間連続キャプチャ。これは学習/検証/テスト分割で重要になる。
時間リーク回避のため **ファイル単位・時系列順**(シャッフルなし)で分割する。

## CSVフォーマット

セミコロン区切り、1行=1 CANフレーム、先頭にヘッダ行。

```
timestamp;id;dlc;data
2020-11-23 08:03:31.985194;0x10ff80e6;8;0;0;251;109;240;144;255;255
2020-11-23 08:03:31.988986;0x1cff80e6;1;230
```

| 列          | 意味                                                            |
|-------------|-----------------------------------------------------------------|
| `timestamp` | `YYYY-MM-DD HH:MM:SS.ffffff`、マイクロ秒精度                     |
| `id`        | 29ビット拡張アービトレーションID、16進(例 `0x18f004e6`)         |
| `dlc`       | データ長(バイト)。大半は8、1・3・4も観測                      |
| `data`      | `dlc` 個の **10進** バイト値(0〜255)を各列に                   |

先頭3列(`timestamp`・`id`・`dlc`)は固定で、その後ろに `dlc` 個のデータバイトが
並ぶ。つまり1行の総列数は「3 + dlc」になる。

- 例: `dlc=8` は 3 + 8 = **11列**(データバイトは4〜11列目)
- 例: `dlc=1` は 3 + 1 = **4列**(データバイトは4列目の1個だけ)

データバイトは4列目以降に並び、値は **16進ではなく10進**。

## 識別子と信号

29ビットIDが PGN(メッセージ種別)とソースアドレスにどう分解されるかは、コードの
隣の [preprocess/docs/can_id_decompose.md](../preprocess/docs/can_id_decompose.md)
に記載。PGNは1つ以上の SPN(車速やエンジン回転などの個別信号)を運び、固定の
スケールとオフセットでペイロードから物理値に変換される。フィールドの完全な定義は
SAE J1939 規格を参照。

## プロファイリング結果(`part_1` の1ファイル、約5万行、約10分)

- **ユニークPGN 57種**、**ソースアドレス 10種**。
- ソースアドレス **`230`** が全フレームの約78%を占める(主パワートレインECU)。
- DLC分布: `8`(大多数)、`4`、`1`、`3`。
- **対象SPNは実在**(メッセージ, PGN):
  - `EEC1`(61444) エンジン回転、エンジントルク
  - `EEC2`(61443) アクセルペダル、エンジン負荷率
  - `CCVS1`(65265) 車輪車速、ブレーキスイッチ
  - `LFE1`(65266) エンジン燃料流量、瞬間燃費
- **`ETC2`(65234)は不在。** 選択ギアはこのPGNから取れないので、別PGNを使うか除外。
- **マルチパケット輸送(TP)は存在するが無視できる量。** TP.CM(60416)と
  TP.DT(60160)が少数出現するが、対象SPNは運ばない。再組立は不要なので、これらの
  PGNはホワイトリストに載せるだけ。

PGN別頻度は仮定せず実測する(例: サンプルファイルのEEC1は約5 Hzで、教科書的な
20 msではない)。したがって **PGN別の周期基準は学習データから実測**し、J1939の
公称周期は使わない。

## 前処理への含意

1. **デコードはPGNをキーにし、優先度とSAも保持する。** バイトの意味はPGNだけで
   決まる(同じPGNなら送信元・優先度が違っても信号レイアウトは同一)ので、デコード
   表の照合はPGN単独でよい。優先度とSAは破棄せず保持し、後段のルールによる異常の
   振り分け(なりすまし=SA、DoS=優先度+周期 など)で使う。
2. **統計は学習データからのみ算出する。** 正規化の値域、PGN別周期基準、検知閾値は
   すべて学習分割でfitし、検証とテストへ適用する(リーク回避)。
3. **時系列順・ファイル単位で分割する。** シャッフルなし。既定は
   `part_1..part_3` を学習/検証、`part_4` をテスト。
4. **異常はテスト分割にのみ注入する。** 学習と検証は正常トラフィックだけを見る。
5. **当面はTP再組立をしない。** TPのPGNはホワイトリストに載せ、対象SPNがマルチ
   パケット内に見つかった場合のみ再検討する。
