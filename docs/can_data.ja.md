# CANバスデータセット

本プロジェクトで使う生CANデータの説明。ここには「データが何か・どう並んで
いるか・プロファイリングで分かったこと」を記録する。

英語版: [`can_data.md`](can_data.md)

## 出所

- **車両**: Renault Euro VI 大型トラック(単一車両)。
- **収集**: 実路走行(ダイナモではない)。
- **規格**: SAE J1939 / FMS、250 kbit/s、全データフレーム、拡張(29ビット)ID。
- **内容**: 正常トラフィックのみ。記録内に攻撃・異常は含まれない。
- **原典**: トゥルク大学(University of Turku)J1939 トラックデータセット。
  https://etsin.fairdata.fi/dataset/7586f24f-c91b-41df-92af-283524de8b3e/data

## ディスク上の構成

```
data/
  part_1/   CSVファイル 約2,800
  part_2/   CSVファイル 約2,800
  part_3/   CSVファイル 約2,800
  part_4/   CSVファイル 約2,800
```

- CSVファイルは合計 **約11,194**。
- 各ファイルはきっかり **50,001行**(標本1,200ファイル中1,200ファイル)。
- 総フレーム数は **約5.6億** のオーダー。

各ファイルは独立したキャプチャだが、**時間的に連続しているとは限らない**。記録が
途中で停止して再開することがあり、通常のログの中に長い空白が1つ空く。

| 1ファイルの時間幅 | 割合 |
|------------------|------|
| 約59秒(p1〜p90 が 58.6〜59.4秒) | 約98% |
| 2分超  | 2.2% |
| 10分超 | 1.6% |
| 1時間超 | 0.8% |

つまり典型的なファイルは **約1分** の記録で、毎秒約850フレーム。標本中の最長は
**70.8時間** で、50,001フレームが1つの70.6時間の空白の前後に分かれている。

## CSVフォーマット

セミコロン区切り、1行=1 CANフレーム、先頭にヘッダ行。

```
timestamp;id;dlc;data
2020-11-23 08:03:31.985194;0x10ff80e6;8;0;0;251;109;240;144;255;255
2020-11-23 08:03:31.988986;0x1cff80e6;1;230
```

| 列          | 意味                                                            |
|-------------|-----------------------------------------------------------------|
| `timestamp` | `YYYY-MM-DD HH:MM:SS.ffffff`、マイクロ秒精度                     |
| `id`        | 29ビット拡張アービトレーションID、16進(例 `0x18f004e6`)         |
| `dlc`       | データ長(バイト)。大半は8、1・3・4も観測                      |
| `data`      | `dlc` 個の **10進** バイト値(0〜255)を各列に                   |

先頭3列(`timestamp`・`id`・`dlc`)は固定で、その後ろに `dlc` 個のデータバイトが
並ぶ。つまり1行の総列数は「3 + dlc」になる。

- 例: `dlc=8` は 3 + 8 = **11列**(データバイトは4〜11列目)
- 例: `dlc=1` は 3 + 1 = **4列**(データバイトは4列目の1個だけ)

データバイトは4列目以降に並び、値は **16進ではなく10進**。

## 識別子と信号

29ビットIDが PGN(メッセージ種別)とソースアドレスにどう分解されるかは、コードの
隣の [preprocess/docs/can_id_decompose.md](../preprocess/docs/can_id_decompose.md)
に記載。PGNは1つ以上の SPN(車速やエンジン回転などの個別信号)を運び、固定の
スケールとオフセットでペイロードから物理値に変換される。フィールドの完全な定義は
SAE J1939 規格を参照。

## プロファイリング結果(全4パートから1,200ファイル、60,001,200フレーム)

- **ユニークPGN 57種。** 1ファイルあたりは52〜57種(中央値55)で、52種は全ファイルに
  出現する。**ソースアドレスは10種**で、うち主パワートレインECUの `230` が全フレーム
  の75.9%を送信する。次点の5つは各3.5〜3.9%。
- DLC分布: `8` が **98.22%**、以下 `4` 1.19%、`1` 0.59%、`3` 0.01%未満。
- **公開PGNが41種、プロプライエタリが16種**で、それぞれフレームの76.1%と23.9%を
  占める。プロプライエタリ側は公開SPN定義がないためデコードできない。
  [pgn_classify](../preprocess/docs/pgn_classify.md) を参照。
- **EEC1、EEC2、CCVS1、LFE1 は全ファイル(100%)に存在**(フレーム占有率, 周期):
  - `EEC1`(61444) 5.91%、20ms周期、エンジン回転とエンジントルク
  - `EEC2`(61443) 2.36%、50ms周期、アクセルペダルとエンジン負荷率
  - `CCVS1`(65265) 1.18%、100ms周期、車輪車速
  - `LFE1`(65266) 1.18%、100ms周期、エンジン燃料流量
- `ETC2`(61445)は全ファイルに10Hzで存在し、SPN 524 選択ギアと SPN 523 現在ギアを
  積む。観測値は `-1` リバース、`0` ニュートラル、`1`〜`12`。未対応値 `0xFF` が
  フレームの0.68%。
- **マルチパケット輸送は少量だが常に存在。** TP.CM(60416)がフレームの0.25%、
  TP.DT(60160)が0.74%。どちらも対象SPNは運ばない。

周期は(PGN, ソースアドレス)ストリームごとの到着間隔の中央値であり、フレーム数を
ファイルの時間幅で割った値ではない。後者は空白を含むファイルで過小評価になる。
1ファイルの以前のプロファイルが EEC1 を実際の50Hzではなく5Hzとしたのはこれが原因。
