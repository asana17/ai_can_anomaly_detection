# ルールの測定

[instant](instant) と [rate](rate) のルールが依拠する測定と、測って採用しなかった
候補の記録。データセット自体の測定は
[can_data/measurements.ja.md](../can_data/measurements.ja.md) にある。

英語版: [`measurements.md`](measurements.md)

## ルールが依拠するもの

### ルールが発火する頻度

[rules](README.md) の全ルールを全ログで217,971,171回、デコード1フレームにつき1回
評価した結果。割合の分母は全評価なので、各ルールのドキュメントが載せる値より小さい。あちらは
そのルールが適用される評価だけを分母にしている。

| ルール | 発火 | 割合 |
|---|---|---|
| range_check | 0 | 0% |
| speed_agreement | 37,941 | 0.0174% |
| shaft_ratio | 342 | 0.0002% |
| gear_ratio | 9,891 | 0.0045% |
| steering_sign | 7,105 | 0.0033% |
| engine_off | 1,836 | 0.0008% |
| pedal_conflict | 58,420 | 0.0268% |
| stopped_shaft | 110 | 0.0001% |
| reverse_speed | 297 | 0.0001% |
| reserved_moving | 0 | 0% |
| いずれか | 113,201 | 0.0519% |

2本以上が同時に発火する評価は2,579回。

### 評価が読む行での発火

評価が読むのはグリッドの走行中の行で、全ログで2,757,787行ある。ここでルール全体の
発火は1,645行、0.0596%で、モデルの閾値が切る0.1%を下回る。そのために3つの上限を
変えた。

| ルール | 変更前 | 変更後 |
|---|---|---|
| steering_sign、MIN_YAW 0.02 から 0.05 | 2,545 | 191 |
| shaft_ratio、5 km/h から 20 km/h | 1,176 | 15 |
| pedal_conflict、PRESSED 1% から 10% | 1,066 | 620 |
| いずれか | 5,472 | 1,645 |

残りは speed_agreement 587、gear_ratio 317、reverse_speed 9 で、他は0。
test_sets/20260924-064408 では、ルールだけで10行持続のとき1,089件中483件の攻撃を
捕まえ、誤警報は1時間に0.29回。3つの変更前は543件と1.84回だった。

engine_off は入力軸を外し、stopped_shaft はタコグラフも0を条件にした。どちらも変更の
前後とも走行中の行では発火しない。変わるのは停車中の評価で、141,110件が1,836件、
2,600件が110件になった。

range_check 以外で、4本は同じ量の2つの読みか、2つの間の固定比を見ている。別の4本は
他に何が成り立つかを問うて得たもので、走行中以外にもルールが届くようになったのはこの
4本による。reserved_moving は、他のルールが判定しない走行中の予約値を見る。

全ログ、デコード1フレームにつき1回の評価。

| ルール | 問うていること | 正常データで外れる頻度 |
|---|---|---|
| steering_sign | 操舵角とヨーレートが同じ向きか | 5 km/h・0.02 rad/s 超の28,095,820件中85,134件 |
| engine_off | エンジンが0のとき、駆動される5信号も0か | 36,041,922件中1,836件 |
| pedal_conflict | 両ペダルが同時に10%を超えて踏まれていないか | 216,709,675件中58,420件 |
| stopped_shaft | 両速度が0のとき出力軸も0か | 閾値は50 rpm、超えるのは110件 |

VDC2 を見るのは steering_sign だけである。あの信号は大きさでは検査できないが、
向きなら検査できる。

[change_limit](rate/docs/change_limit.md) は表に入っていない。1行を読むのではなく、
行を前の行と比べる。走行中の行では87行で発火し、うち68行は instant のルールが発火
しない行。これを加えるとルール全体の発火は1,713行、0.0621%。

### 定義域を外れる値は無い

デコードした値はすべて、`spn_spec` が記録する J1939 の定義域と照合している。全ログで
17信号・565,906,098値になるが、外れるものは1つもない。ルール層のレンジ
チェックは、このデータでは誤検知ゼロから始められる。

### 各信号が動ける速さ

走行中のグリッド行と、その前の行との間で測定。前の行は同じセグメントで1 tick前、
かつ走行中の行。全ログで2,749,873ステップ、秒あたり。

| 信号 | 1e-4 | 1e-5 | 最大 |
|---|---|---|---|
| engine_speed | 2,114 rpm | 2,509 | 2,825 |
| driver_demand_torque | 350 % | 610 | 930 |
| actual_engine_torque | 250 % | 360 | 490 |
| accel_pedal | 340 % | 642 | 1,000 |
| engine_load | 360 % | 530 | 730 |
| wheel_speed | 21.0 km/h | 37.0 | 317 |
| fuel_rate | 186 L/h | 305 | 471 |
| output_shaft_speed | 320 rpm | 500 | 4,850 |
| clutch_slip | 460 % | 980 | 1,000 |
| input_shaft_speed | 8,120 rpm | 10,590 | 14,160 |
| selected_gear | 120段 | 120 | 120 |
| current_gear | 80段 | 100 | 110 |
| tachograph_speed | 21.0 km/h | 33.0 | 317 |
| brake_pedal | 144 % | 212 | 360 |
| steering_angle | 7.38 rad/s | 9.39 | 11.1 |
| yaw_rate | 0.283 rad/s2 | 0.364 | 0.488 |
| lateral_accel | 20.4 m/s2 | 28.9 | 46.0 |

[change_limit](rate/docs/change_limit.md) はこのうち7信号に、1e-5の値の少し上で上限を
置く。1e-4で置くと7信号で1,693行発火し、ルール全体は3,118行で0.1%を超える。
accel_pedal と clutch_slip は1行で定義域の端から端まで動き、ギア番号は数段飛ぶ。
変速で入力軸が解放される。

## ルールにならなかったもの

### 一致するはずだった信号の組

以下の4組はどれも、同じ量を2通りに読んだものである。だから一致するはずで、ルールは
その一致を検査できる。成立するかどうかは、正常データで2つがどれだけ離れるかを、その量
自体が動く範囲と比べて決まる。

全ログの5 km/h 超の評価で測定。ずれは2つの差の p99、範囲は1つ目の大きさの p99。

| 組 | ずれ p99 | その量が動く範囲 | 比 |
|---|---|---|---|
| wheel_speed と tachograph_speed | 0.91 km/h | 85.51 | 1.1% |
| engine_load と actual_engine_torque | 12.0ポイント | 87.01 | 13.8% |
| lateral_accel と 車速×yaw_rate | 0.85 m/s2 | 1.33 | 63.9% |
| accel_pedal と driver_demand_torque | 30.4ポイント | 85.21 | 35.7% |

最初の組は86 km/h の範囲に対して0.91 km/h しか離れないので、そのすぐ上に閾値を置けば
ほとんどの改竄を捕まえられる。これが [speed_agreement](instant/docs/speed_agreement.md)
である。残り3組は範囲の14〜64%離れるので、閾値で捕まえられる余地が少なく、ルールを
書いていない。

組を相関で選別してはいけない。最後の組の相関は0.924ある。

### 成り立たなかった他の主張

他に5つの形を試した。いずれも正常データが破らないはずの主張である。全ログ、デコード
1フレームにつき1回の評価で、トルクと燃料の主張はエンジン稼働中の評価で測定。

| 主張 | 正常データが破る頻度 |
|---|---|
| 後退中は低速のまま | 26,197,193件で最大38.3 km/h |
| 稼働中のエンジンは燃料を使う | 9.8%。惰行時の燃料カット |
| 実トルクは要求トルクを超えない | 48.0% |
| 実トルクはエンジン負荷を超えない | 1.8% |
| 選択ギアと現在ギアは1段差に収まる | 最大12段 |

全ログではどれも成り立たない。[reverse_speed](instant/docs/reverse_speed.md) は
87,245件で3.5 km/h を超えなかったことから最初の主張で作ったが、全ログでは297件
発火する。

### 入力軸を検査しない理由

未実装のルール候補。クラッチが閉じていれば両者は一緒に回るはずである。全ログの5 km/h
超・スリップ0の評価で、p90 では 3.9 rpm 以内に収まる。しかし4.21%では50 rpm を超えて
食い違い、最大1,518 rpm になる。
一例はエンジン1552に対し入力軸934、報告されるスリップは0。

ETC1 のバイト1が駆動系とトルクコンバータの状態を持ち、理由を説明できるはずだが、この
データでは全ログで204、205、220、221の4値と0xFFしか取らずビットを確定できない。確定するまで、4.21%は
既存のルールより2桁悪い。

### 書いていないメッセージ側の検査

あと4つ検査が作れる。メッセージの種類ごとに周期が固定で、送信元が固定で、バイト数が
固定で、そもそも57種類しか現れない。いずれも上で測定済みである。

これらが捕まえるのは別種の攻撃で、フレームを追加する、落とす、偽造する類のものである。
そうした攻撃をまだ合成していないため、突き合わせる対象が無く、どれも書いていない。
